# Registro de decisiones de arquitectura (ADR)

La base autorizada y las elecciones de configuración se registran en [ADR 0001](0001-base-de-desarrollo.md). La arquitectura de producto sigue pendiente. Usa números consecutivos, por ejemplo `0001-eleccion-del-stack.md`. Antes de crear uno, revisa los existentes para no colisionar.

Copia [la plantilla](../templates/ADR.md), describe contexto, alternativas, decisión propuesta, consecuencias y validación. Estado: propuesto → aceptado/rechazado; si cambia un acuerdo, crea otro ADR que lo sustituya y enlaza ambos. Conservar razones históricas.

Sólo marcar aceptado tras acuerdo explícito del equipo; registrar fecha y responsables. El agente puede proponer, no fingir aprobación. Actualiza `../DECISIONS.md` y las guías afectadas en el mismo cambio.
